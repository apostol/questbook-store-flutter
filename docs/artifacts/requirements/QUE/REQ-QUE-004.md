## Формулировка
Система должна открывать 100% сохранённых прогрессов предыдущей выпущенной сборки среза (3 из 3 состояний: старт, после выбора, концовка) после обновления на следующую сборку без потери данных и без падений; при несовместимом формате — начинать историю заново с уведомлением.

## Условия проверки
- Сборка: release, целевая платформа Android (REQ-QUE-006), одинаковый signing key у обеих сборок.
- Подготовка: установить предыдущую выпущенную сборку среза (N), создать 3 фикстуры прогресса:
  стартовый фрагмент, фрагмент после выбора, концовка.
- Проверка: обновить приложение до следующей сборки (N+1) без удаления данных, открыть приложение.
- Критерий: 3 из 3 фикстуры открываются без потери данных и без падений (100%); для
  несовместимого формата — история начинается заново с уведомлением по решению
  `docs/decisions/2026-11-22-corrupt-progress-behavior.md`, без падения.
- Совместимость проверяется только вперёд, N → N+1; откат на предыдущую версию и перенос между
  устройствами вне среза.

## Обоснование порога
Формат и версионирование прогресса — решение SA. Порог 100% на трёх состояниях — минимум,
который отличает рабочее обновление от потери прогресса; расширение числа версий и состояний —
отдельное требование, а не молчаливое допущение.
