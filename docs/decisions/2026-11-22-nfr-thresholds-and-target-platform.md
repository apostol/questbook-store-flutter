# Численные NFR первого среза и целевая платформа Android

## Контекст

Feature QUE-2 и User Story QUE-3 блокированы до фиксации численных NFR и целевых платформ:
BA-этап завершён, BA-ворота `ready=true`, разработка не начиналась. Project Owner решением
`docs/decisions/2026-11-22-nfr-and-target-platforms.md` передал значения порогов и состав
платформ владельцу требований (Project Manager), запретив выдумывать их на стороне PO.

Репозиторий — Flutter-проект с каталогами Android, iOS, Linux, macOS, Web и Windows
(`.metadata`). Единственная документированная среда сборки и запуска — WSL2 + Android SDK
и эмулятор (`README.md`; AVD `test-emu`, system image `android-30;default;x86_64`);
`android/app/build.gradle` задаёт `compileSdkVersion 30` и `targetSdkVersion 30`.
Измеренных UX-порогов и исследования производительности в проекте нет.

## Основание

- `docs/decisions/2026-11-22-nfr-and-target-platforms.md` — порядок и делегирование
  владельцу требований; продуктовые ограничения среза: гостевая работа без сети, прогресс
  только на установке, одна история, публичный запуск вне среза.
- `docs/artifacts/specs/SPEC-ID-001-guest-test-story-progress.md` — Feature QUE-2, NFR-001 и
  критерии AC-1…AC-3.
- `docs/artifacts/specs/SPEC-QUE-002-guest-test-story-local-continue.md` — User Story QUE-3,
  NFR-001 и путь отказа прогресса.
- `docs/artifacts/analysis/epic-QUE-1.md` — открытый вопрос о NFR и платформах.
- `docs/decisions/2026-11-22-corrupt-progress-behavior.md` — поведение при повреждённом или
  несовместимом прогрессе.
- `docs/artifacts/content/QUE-BUNDLED-001-kniga-kotoruyu-nikto-ne-otkryval.md` — встроенная
  история: 3 фрагмента, одно ветвление, одна концовка; нагрузка только локальная.
- `README.md`, `android/app/build.gradle`, `.metadata` — фактическая платформенная конфигурация
  репозитория.

## Решение

1. **Целевая платформа первого среза — Android.** Проверка проводится на Android API 30
   (`targetSdkVersion 30`): AVD `test-emu` из `README.md` или физическое Android-устройство,
   согласованное с QA. iOS, Linux, macOS, Web и Windows остаются в репозитории, но вне объёма
   среза: их сборка и проверка не требуются и не обещаются (REQ-QUE-006).
2. **Численные NFR среза:**
   - REQ-QUE-001 — холодный запуск до первого фрагмента: не более 3,0 с, 5 из 5 запусков;
   - REQ-QUE-002 — переход между фрагментами: не более 0,5 с, 10 из 10 переходов;
   - REQ-QUE-003 — сохранность прогресса после перезапуска: 10 из 10 обычных закрытий и
     10 из 10 принудительных остановок без потери последнего подтверждённого выбора;
   - REQ-QUE-004 — совместимость прогресса при обновлении предыдущей выпущенной сборки среза
     на следующую: 100% из 3 состояний (старт, после выбора, концовка), 0 падений; при
     несовместимом формате — начать историю заново с уведомлением;
   - REQ-QUE-005 — работа без сети: 100% шагов гостевого сценария, 0 обязательных сетевых
     запросов, 0 блокирующих ошибок сети.
3. Значения — **приёмочные границы первого среза**, а не измеренный baseline и не продуктовая
   метрика. Они проверяются QA по процедурам в файлах требований.
4. Безопасность и доступность отдельными численными NFR в минимальный набор не входят:
   гостевой срез не вводит аккаунты, платежи и передачу персональных данных; доступность
   (accessibility) — названный пробел, а не молчаливое допущение. При необходимости они
   вводятся отдельными требованиями.
5. Формат хранения, версионирование и обнаружение несовместимости прогресса остаются решением
   SA; REQ-QUE-004 задаёт только проверяемое поведение.

## Отвергнутые альтернативы

- **Все Flutter-таргеты (Android, iOS, Linux, macOS, Web, Windows) и полный набор NFR.**
  Отклонено для первого среза: единственная документированная среда — Android; iOS и macOS
  требуют Apple-инструментов, Web/Windows/Linux не проверялись; это расширяет работу SA, QA и
  Dev и откладывает перевод Feature в todo без подтверждённой выгоды.
- **Срез без численных NFR как прототипный.** Отклонено Project Owner: приёмка стала бы
  субъективной, у QA не было бы проверяемых критериев качества
  (`2026-11-22-nfr-and-target-platforms.md`).
- **Вынести NFR в отдельную задачу и не блокировать срез.** Отклонено Project Owner: NFR и
  платформы — предпосылка разработки и проверки, а не последующая работа.

## Последствия

- Первый срез поставляется только на Android; остальные платформы не тестируются и не обещаются.
- Пороги могут быть пересмотрены только новым решением владельца требований с указанием
  измерений; молчаливое ослабление проверки запрещено.
- QA создаёт тестовые задачи на REQ-QUE-001…006; Project Owner переносит значения в
  SPEC-ID-001, BA — в SPEC-QUE-002 и документ истории.
- В проекте отсутствует устав `docs/artifacts/project/charter.md`; это названный пробел,
  который не блокирует численные NFR первого среза, но не позволяет проверять прогноз конца
  проекта и контрольные точки.
- Значения не являются подтверждённой продуктовой метрикой; продуктовая метрика остаётся
  открытой до `business-case.md`.
